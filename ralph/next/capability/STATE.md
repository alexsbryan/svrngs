# svrngs capability — what can act as you, one deliverable (operator, 2026-10-23)

svrn-docs `rings/current/WHAT_CAN_ACT_AS_YOU.md` holds svrngs to one rule,
by capability: what can act as you is what you chose, never widened
silently (§1, §2). The operator bundled its work into one deliverable and
one release (2026-10-23: "I'd like to bundle it all in with" that note): the
security fixes it found (§3, §6), consent you can see, and authorship by
signature with keys everywhere (§10). The streaming test's stall runs first
and alone, in `ralph/next/stall/` ("Now, alone").

Why one: the phone's key is placed once, for the pass (shortfall 4) and for
the phone's own signature; the door's reach changes once, for navigations
(6) and for the yes to `--reads` (3); and the interim version-pin fix is
dropped, since authorship closes shortfalls 1, 2 and 8 at the root in the
same release (the operator: "Drop it").

**Decided** (the note's §7, 2026-10-22): a yes per app for `--reads`; only
carry what you signed; first open is the yes; keys everywhere. **The UX
line:** "make this as lightweight as possible so it's not onerous friction",
so no new step blocks anyone (§9). **Capabilities, not buckets:** each rule
is said by what code can do as a person, never by what kind of app it is.

There are twelve rows:
1. an economizing pass, an estimate, and the ceiling;
2. navigations through the door (shortfall 6);
3. Money's corrections (9);
4. the demo scenes, played end to end on every gate (the operator,
   2026-10-23), so every row after is held to them;
5. the phone's key (4);
6. what the scenes found: a restarted peer, a joiner's phone, a scene that
   needs a network, and each scene's timing judged against the load bar
   (the operator, 2026-10-23: "Route them now"), before the rows whose
   gates the scenes hold;
7. the open says what an app does, and is the yes (3, 7);
8. "What acts as you";
9. authorship: the act format, stopped for the operator, run at high from
   here on (`HUMAN-effort-high`);
10. authorship: each device signs its own acts (1, 2, 8);
11. keys everywhere;
12. the docs and a release, prepared for the operator.

**Waits, each with its trigger** (PLAN §2):
- sealing an entry to some keys: two apps need the same seal (lending, Tap;
  the note's §10, 4);
- an app declaring what it needs, so the lender only agrees in place of
  typing `--reads` (§11): the first app outside svrngs's own that needs
  `--reads` (the operator, 2026-10-23: "Wait, with a trigger");
- a sandboxed carried page: code arriving from outside a person's rings (§5);
- the capability core as a move of its own: a third change touching its
  sites (§10, 2).
