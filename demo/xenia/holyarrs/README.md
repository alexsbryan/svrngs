# Warranty the newcomer's film journey

Operator direction, 2026-11-10: "Just warranty the work; we have the tools to
discern this with near-analytical certainty." Written before these runs.

## The owned claim

For the checked build, an ordinary newcomer can get from the invitation they
actually receive to finding and playing a friend's film, and asking for a
missing film, using the product's own explanations. Every necessary instruction,
account and transition has a visible source. A discovered blocker is ours to
reproduce, fix and retest.

This is an engineering warranty over a named journey and its stated conditions.
Deterministic facts, model observations and unexercised conditions retain their
own verdicts. Xenia's participants remain explicitly simulated; their completion
does not become a fabricated observation about a real person or a population.

## Conditions and actors

- Ana already keeps a configured HolyArrs and Jellyfin and lends them to Friends.
  The real services, private torrent seed/downloader and explicit metadata/source
  fixtures reuse `apps/holyarrs/check/`. Host installation and content acquisition
  setup are declared prerequisites, not a newcomer's unseen accomplishment.
- The newcomer starts outside Friends in an empty browser profile. There is no
  pre-joined native Bo, no own-device shortcut, and no preaccepted request-app
  invitation. Any viewing credentials prepared by the host must be in the
  newcomer's actual message, as they would be for the host's existing server.
- The chat message contains only what Ana can produce from her actual pages and
  ordinarily tell a friend. No selectors, route names or backstage advice reach
  a simulated newcomer. If an application invitation cannot travel from Ana's
  computer to a friend's device, that is a failing transition to fix.
- The friend's first supported path is the phone/browser path: joining needs no
  native installation. The computer path's downloaded installer, copied command,
  browser arrival and persisted identity are checked independently by the
  existing cold-install instruments, with their exact artifact/build provenance.

## Three complementary instruments

1. **Required-action map.** For each task, record the starting screen, the words
   that explain the next action, the actionable control, the resulting state,
   and the recovery edge. Trace every credential and URL to its visible source.
   A hidden prerequisite, ambiguous destination, dead end, or guessed instruction
   is a defect. Existing product copy and guides are held to the actual screens.
2. **Cold-start construction proof.** A deterministic browser driver exercises
   every required transition against the real services, from fresh membership
   and application accounts. Independent observers verify membership, request
   authorship/approval, the imported bytes and Jellyfin's playing identity/item.
   This extends the existing H1-H8 media proof rather than replacing it.
3. **Blind newcomer rehearsal.** Xenia supplies the stranger, reading/time
   accounting and model-admission plants. Run an exploration first, then the
   corrected journey repeatedly with frozen cautious and impatient novice
   profiles. DeepSeek Flash uses explicit `max` effort. The model sees its
   message and browser senses only; the stage and service observers decide facts.

   A journey has steps: visible joining, joined group, opened search, viewing
   sign-in, found film, invitation, created account and found request. Declare
   these as the scene's `reach` milestones, using visible page state rather than
   a bare origin's bootstrap page. Each recharges the frozen person's existing
   step allowance once; none declares a task successful. Before interpreting a
   patience failure, verify Xenia actually applies those declared milestones.

An assistant-authored click script is instrument evidence. An independent Xenia
completion is discoverability evidence. Neither silently stands in for the other.

## Journey and checks

| Check | What must be established |
|---|---|
| N1 — arrival | The ordinary invitation reaches the correct group in an empty browser. The person chooses their own name; no hidden existing membership is used. |
| N2 — first accounts | Required app accounts can actually be obtained using the message and visible UI. An invitation produced on the lender's computer opens on the friend's device. |
| N3 — find and watch | Movie Night is findable from the group, its permission explains the actual libraries, and following the chosen copy leads to that item and actual playback as the newcomer. |
| N4 — ask | A missing title can be requested through HolyArrs as the newcomer's own account, with approval visibly pending and the host able to identify its author. |
| N5 — come back | Refresh/reopen returns to the same group/person and app account. Wrong password, a temporarily unavailable lender and a stale/closed invitation each have a visible next step. |
| N6 — computer construction | A cold installer uses the page's actual command/artifact, reaches the intended group, opens its own authenticated page and retains identity on retry. Its proof names which OS/build ran. |
| N7 — discoverability | Frozen blind profiles complete the supported browser tasks without an operator's hint. Counts, hard faults, outside requests and assistance are read from Xenia's trace; a model's own claim is insufficient. |
| N8 — retained warranty | Every row has a verdict and evidence at the checked source/build. Every discovered blocker has a reproducer and regression. Missing evidence stays owed, never passed. |

Existing bars apply where they fit: NORTH_STAR's ten seconds for the group join's
own transition; `demo/b.md`'s three minutes from a link to the film; and the
existing onboarding bar for cold computer arrival. Model inference time and
download/acquisition time are recorded separately from an interface's own wait.
One exploration is not a completion rate. An analyst's proposed threshold is
never presented as an observed human limit.

## Controls, before trusting the result

- Withhold the invitation/credential the friend needs: N2/N3 cannot pass.
- Close the ordinary group invitation before an empty profile uses it: N1 must
  report refusal, not reuse another actor's membership.
- Use a lender-local application invitation from the friend's context: N2 must
  catch an unreachable or wrong origin before a corrected link is credited.
- Keep the film absent or the readers' account unavailable: N3 must fail at the
  independently observed missing copy/read, as H4's existing plant does.
- Deny playback or substitute another item: a visible Play alone cannot pass N3.
- Xenia runs its own model-admission plants with the same model/effort. A missed
  plant makes the corresponding model evidence could-not-judge; it cannot be
  used to sign a discoverability warranty.

## Execution and record

run the controls and deterministic journey, then admit the model and run blind
profiles. Fix the product or its ordinary instructions at the boundary that owns
the demonstrated problem. Use the same prompt after a fix; add no hint to make
the actor pass. Preserve the red runs and exact source fingerprints.

Keep private app/group invitations, passwords, raw browser bodies and live
transcripts under `target/`. Record sanitized action maps, findings, screenshots,
