== node web/tests/dev.mjs
Your group's page is at https://group.svrnme.test:55502/, for this computer only.

Open it in a Chrome of its own: paste this in another Terminal window.

  open -na "Google Chrome" --args --user-data-dir="$(mktemp -d)" --no-first-run --proxy-server=http://127.0.0.1:55503 --ignore-certificate-errors-spki-list=2BNB5D4yvdolPkeLHwvE5Hr6bIQaMCAVJEgaWPFG1FE= https://group.svrnme.test:55502/

That Chrome reaches the page through this command, and takes its certificate, which nothing else trusts. It keeps nothing you already use.

To join a group there, open any link to it in that Chrome, with what comes before the # changed to https://group.svrnme.test:55502/ (for a svrngs://join/ link, svrngs://join/ changed to https://group.svrnme.test:55502/#).

Or point a group at this page, so svrngs prints its links here. Stop svrngs, then run one of these, which runs it again:

  svrngs new <name> --origin http://localhost:55502/
  svrngs link <group> --origin http://localhost:55502/

svrngs checks the page at http://localhost, since nothing but that Chrome reaches the https address, so its links start http://localhost:55502/. Change that to https://group.svrnme.test:55502/ too: at http://localhost, apps don't open. A new link stops the group's old one letting anyone in. --origin https://group.svrnme.sh/ points it back.

Safari can't save in an app here. It keeps the page's cookie from the app on every local address (demo/runs/security/2026-11-02-webkit-partition/).

After a change, run scripts/build-web.sh again and reload. Ctrl-C stops this.
