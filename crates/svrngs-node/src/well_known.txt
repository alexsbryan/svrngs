# llama-server, llama.cpp's own server (start-llama). Its default port, 8080,
# is Open WebUI's and many dev servers' too, so svrngs does not take a port for
# it: its lender says `--kind llama-server`, the program's own name, and types
# nothing else. Kept back, as start-measure (b) read llama.cpp 11b068d06 and
# asked each route (demo/runs/start/2026-10-13/README.md §3 (b) 6-10):
#   /slots           when each person's chat runs, how long, with what
#                    settings; /slots/<id> saves and erases them on the disk
#   /v1/stream, /v1/streams, /v1/chat/completions/control
#                    another person's chat read from its start, stopped, or
#                    its reasoning ended, given its id (the run read Cy's)
#   /lora-adapters   changes the model for everyone
#   /metrics         the server's load (on only with --metrics)
#   /tools           runs a shell on the lender's computer (with --tools)
#   /cors-proxy      fetches any address from it (with --webui-mcp-proxy)
#   /models          loads and removes models (router mode); GET /models is
#                    /v1/models's twin, which stays

# path back for every method alike (svrngs-node lend.rs, RefusedPath::covers);
# POST /props answers only with --props. Its `model_path` shows everyone the
# model's file on the lender's disk, the account's name in it: svrngs does not
# change an answer (DESIGN §3, "Lent apps, as they come").
